# Native JSON persistence on R2

Implemented locally: `authority/object_store/`, `authority/rings/persistence.rs` and `deployment/cloud-bridge/`. No live bucket or credentials were created or tested. There is no SQL conversion, Cloud SQL or Firestore in this path. The older passkey owner service remains SQLite-based. A separate native owner path now commits credential counters/revocations and ring changes in one JSON aggregate, with synthetic lifecycle tests. No existing account was migrated; native HTTP/browser/concurrency review remains. See [prototype status](prototype-status.md).

Immutable snapshots use `<user_hash>.<contenthash>.json`. A small `<user_hash>.head.json` points to the current snapshot. SHA-256 covers Signet's canonical JSON envelope (sorted object keys, integer numbers only), user scope, monotonic revision, previous pointer and state. This is a versioned Signet format, not a claim of RFC 8785 compatibility. Identical logical ring definitions have separate content hashes; complete authority snapshots also include history and replay state.

A transition loads the uncached current head and its verified snapshot, checks signed authority and all conditions, writes the immutable candidate with `If-None-Match: *`, then changes the head with the exact opaque prior ETag in `If-Match`. A stale head loses the CAS. No unconditional overwrite or missing-head auto-bootstrap exists. All reservations, budgets, nonces, audit events and request receipts commit together. `Loaded` bases are bound to one user.

Only `CommitOutcome::CommittedNow` may start newly reserved work. `Recovered` must reconcile the original execution, never dispatch again. Exact signed request receipts persist within the ring aggregate: a caller can retry after a lost reply, expiry or later head changes and recover its original output without repeating its effect. Signature authentication remains required. These receipts intentionally do not claim that the original permission is still active. At the lower object-store layer, candidate recovery checks head ancestry, not arbitrary object existence; bounded traversal fails closed when inconclusive.

The Node bridge uses pinned AWS S3 SDK dependencies, explicit R2 endpoint/bucket/credentials, conditional GET/PUT semantics, bounded bodies and request timeout. Rust can invoke it through `NodeBridge`; it neither discovers ambient AWS credentials nor provides list/delete/unconditional write operations. The helper inherits operator-supplied `SIGNET_R2_ACCOUNT_ID`, `SIGNET_R2_BUCKET`, `SIGNET_R2_ACCESS_KEY_ID`, `SIGNET_R2_SECRET_ACCESS_KEY`. Provisioning and rotation are separate, unperformed steps. Account metadata and ring relationships are currently readable to the authority service; encrypted asset payloads have a separate client-custody design.

Retention is a pure planning function, not a deletion worker. An eligible committed version must be older than a chosen age cutoff **and** have at least N newer committed versions, with active heads, pins and in-flight references protected. Neither age nor N has been chosen. The caller must provide a verified committed catalog and a coordination fence; orphan objects cannot establish committed history. Deletion needs separate credentials and a reviewed cleanup worker. No data was deleted.

A lost head or rollback by an administrator is not solved by content hashes alone. Trusted recovery must preserve the newest replay/budget/receipt state, with an externally protected monotonic checkpoint before production. Do not repoint the head at an older authority snapshot.
